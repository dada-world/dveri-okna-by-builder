# Настройка отправки форм

## Проблема
Заявки не отправляются на почту из-за неправильной обработки ответа от сервиса submit-form.com.

## Решение
Добавлен fallback механизм, который:
1. Сначала пытается отправить форму через локальный API (`/api/contact`)
2. Если локальный API не работает, отправляет напрямую в submit-form.com

## Настройка

### Локальная разработка
Создайте файл `.env.local` в корне проекта:
```bash
NEXT_PUBLIC_FORM_ENDPOINT=/api/contact
```

### Продакшн (GitHub Pages)
В GitHub Actions уже настроено:
```yaml
NEXT_PUBLIC_FORM_ENDPOINT: "https://submit-form.com/esY14v503"
```

## Как это работает

### 1. Форма контактов (`ContactForm.tsx`)
- Отправляет данные через локальный API
- Fallback на submit-form.com если API недоступен
- Автоматически добавляет email если не указан

### 2. Форма конфигурации окон (`WindowConfigurationForm.tsx`)
- Аналогичная логика с fallback
- Включает конфигурацию окон в заявку
- Валидация обязательных полей

### 3. API endpoint (`/api/contact`)
- Обрабатывает POST запросы
- Пересылает данные в submit-form.com
- Корректно обрабатывает статус 302 (успешная отправка)

## Тестирование

1. Запустите проект локально: `npm run dev`
2. Откройте форму контактов
3. Заполните и отправьте форму
4. Проверьте консоль браузера на наличие логов
5. Проверьте, что заявка появилась в submit-form.com

## Логирование
Добавлено подробное логирование для отладки:
- Данные формы перед отправкой
- Endpoint для отправки
- Статус ответа
- Результат обработки

## Возможные проблемы

1. **CORS ошибки** - решено добавлением заголовков в API
2. **Отсутствие email** - автоматически добавляется дефолтное значение
3. **Статус 302** - теперь корректно обрабатывается как успех
4. **GitHub Pages** - API routes не работают, используется fallback

## Мониторинг
Проверяйте логи в консоли браузера и в GitHub Actions для диагностики проблем.
